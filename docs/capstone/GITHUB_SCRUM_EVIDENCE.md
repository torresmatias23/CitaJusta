# Evidencia Scrum con GitHub

## Objetivo

Usar GitHub como fuente de trazabilidad del trabajo sin crear en esta fase Issues, Projects ni Milestones artificiales.

## Uso propuesto

| Recurso | Evidencia esperada |
| --- | --- |
| GitHub Issues | Historias de usuario, criterios de aceptación, tareas y defectos |
| Milestones | Sprint, objetivo, fechas y alcance comprometido |
| GitHub Projects | Product Backlog priorizado y estado del Sprint Backlog |
| Branches | Trabajo técnico vinculado a una Issue |
| Pull Requests | Revisión, discusión, cambios y pruebas asociadas |
| Checks/tests | Evidencia automatizada del cumplimiento técnico |

## Trazabilidad

```text
Historia de usuario
-> Issue
-> Sprint/Milestone
-> Branch
-> Pull Request
-> Tests y evidencias
-> Done
```

Cada Pull Request deberá enlazar su Issue, declarar criterios cubiertos y registrar las pruebas ejecutadas. Una historia sólo podrá cerrarse cuando satisfaga la Definition of Done, una vez que ésta sea aprobada por el equipo.

## Convenciones mínimas pendientes de aprobar

- Una Issue identificable por historia, tarea o defecto.
- Prioridad y criterios de aceptación visibles en cada historia.
- Milestone por sprint.
- Branch y Pull Request vinculados a la Issue correspondiente.
- Resultado de pruebas y evidencia académica asociados al Pull Request o al sprint.
- Retrospectiva almacenada en la carpeta académica del sprint, sin datos personales innecesarios.

## Estado

`PARCIAL`: la estrategia queda documentada. No se creó automáticamente ningún Issue, Project, Milestone ni Pull Request.
